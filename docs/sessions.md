# 会话编辑与断线重连

## 编辑已保存的会话

在侧边栏会话列表中右键点击 SSH 会话，选择“编辑会话”。可修改名称、主机、端口、
用户名和密码；保存后更新列表及 `config/sessions.json`，取消则不修改。

名称、主机和用户名不能为空，端口范围为 1–65535。密码保留原始字符，包括首尾空格；
清空密码表示改用现有的 ssh-agent / 私钥认证。密码仍按现有方式保存在会话文件中。

编辑保留记录 ID、所在分组及排序。保存时按 ID 查找记录，因此表单打开期间移动会话
不会误改其他记录；记录已被删除时不会重新创建它。

已打开的终端沿用建立时的连接参数。修改后的配置用于下次从会话列表打开的新终端。

## 重新连接 SSH

SSH 连接结束后，当前分屏右上角显示“已断开 · 重新连接”。点击后使用该终端原来的
连接参数建立新的 SSH shell，保留标签、分屏、终端网格及滚屏。连接中暂时收起按钮，
进度显示在终端内；连接失败后重新显示按钮，可再次重试。不会自动循环重连。

重连沿用主机密钥校验，并使用当前终端尺寸；每次生成新的 SSH / SFTP 连接实例，
重新协商 X11 转发，并等待新 shell 上报工作目录。原连接的延迟事件不会覆盖新状态。
本地终端不会显示此重连入口。

重连不会恢复旧 shell 的进程、环境或工作目录，也不会自动续传旧 SFTP 任务。
需要保留远端任务时，应在远端使用 tmux 等工具。

## 验证

```sh
cargo check --locked --workspace
cargo test --locked -p alacrterm
cargo run --locked -p ssh --example local_server -- 2222
```

本地测试服务的用户名为 `tester`，密码为 `alacrterm-test`。新建连接到
`127.0.0.1:2222` 的会话，可按以下步骤验证：

1. 编辑名称后取消，确认原记录不变；再次编辑并保存，重启应用后确认配置仍然有效。
2. 打开会话并输入任意文本，输入 `exit` 后点击重连，确认原输出保留且新 shell 可输入。
3. 终止测试服务，点击重连，确认失败后仍可重试；重新启动服务后再次重连。
4. 切到文件管理器，确认新连接可以读取目录；其他分屏和标签不受影响。
